# 运行请求：人工排队，不是远程运行服务

任何组员都可以提出实验，持有已验证环境的人负责执行。先提交本目录的请求文件和代码 PR，由另一位组员核对后进入队列。不能把请求文件的存在当成实验已启动。

1. 复制 `example.json`，改成独立请求名。
2. 填好负责人、复核人、已确认的代码提交号、模型/数据来源、参数、预算、评价范围和输出路径。
3. `status` 从 `draft` 开始；复核完成后记为 `queued`，运行时改 `running`，完成后附真实证据。失败记 `failed` 和原因。
4. `example.json` 中为示例和未填字段，不能直接当作已批准或可执行任务。
5. 当前正式入口不支持任意 seed/输出路径，参数化扩展入口仍是待做任务 T05。填写请求不等于已经实现该功能。

已有基线目录不覆盖。建议新增结果路径 `study/runs/<run_id>/`；代码和结果结构需由扩展入口实际支持。结束后由任务提出者解释结果，运行者不承担全部分析。
